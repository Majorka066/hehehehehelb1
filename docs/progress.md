## Результат ЛР 2

Проект из ЛР 1 продолжен без смены темы и репозитория. Пустой раздел заменён полноценным SPA-интерфейсом планировщика мероприятий.

Выполнено:

- установлен `react-router`, версия зафиксирована в `package-lock.json`;
- описан тип `Event` и строковые объединения для статуса и категории;
- подготовлены шесть демонстрационных записей с уникальными `id`;
- создан компонент `EventCard`, получающий объект события через типизированные props;
- список строится через `map`, а стабильный `key` берётся из `event.id`;
- карточка ищется по параметру `:id` через `useParams` и показывает все поля;
- добавлены общий `AppLayout`, `NavLink`, `Outlet` и вложенные маршруты;
- созданы заглушка будущей формы, неизвестная страница и отдельное сообщение об отсутствующем мероприятии;
- стили адаптированы для ширины 360 px, сохранён видимый фокус клавиатуры.

## Маршруты ЛР 2

- `/events` - список;

## Контрольные вопросы и ответы (защита ЛР 2)

1. **Чем страница отличается от повторно используемого компонента?** Страница связана с конкретным URL и собирает целый экран. Повторно используемый компонент решает одну локальную задачу и может многократно получать разные данные.
2. **Что получает `EventCard` через props и зачем здесь тип `Event`?** Карточка получает один объект `event`. Тип `Event` задаёт обязательные поля и допустимые значения, поэтому TypeScript выявляет ошибки до запуска.
3. **Почему `key` должен быть стабильным и где он задаётся?** React использует `key`, чтобы сопоставлять элементы между рендерами. В методе `map` страницы списка задаётся `key={event.id}`, потому что `id` уникален и не меняется из-за сортировки.
4. **Какую роль выполняют `BrowserRouter`, `Routes` и `Outlet`?** `BrowserRouter` связывает React с историей и адресом браузера. `Routes` выбирает подходящий `Route`. `Outlet` показывает выбранную дочернюю страницу внутри общего layout.
5. **Откуда берётся `id` и почему карточка работает после обновления?** Параметр `:id` попадает в URL и читается через `useParams`. Затем запись заново ищется в едином массиве, поэтому выбор не зависит от временного состояния навигации.
6. **Чем отличаются неизвестный путь и отсутствующая запись?** Неизвестный путь вообще не совпадает с маршрутами и обрабатывается `path="*"`. Адрес `/events/missing` совпадает с `/events/:id`, но поиск в данных не находит объект.
7. **Что будет добавлено на страницу создания в ЛР 3?** Рабочая форма с полями мероприятия, валидацией, обработкой отправки и сохранением новой записи.

## Контрольные вопросы и ответы (защита ЛР 3)

1. **Почему список хранится в `App`, а черновик - в форме?** `App` не размонтируется при переходе между страницами, поэтому список остаётся общим для списка и карточки. Черновик нужен только форме и не должен менять сохранённую запись до отправки.
2. **Чем props отличаются от локального состояния?** Props приходят от родительского компонента и не изменяются дочерним напрямую. Локальное состояние принадлежит компоненту и меняется его функцией `setState`.
3. **Почему `push` и изменение `event.title` напрямую здесь не подходят?** Они изменяют существующий массив или объект. React ожидает новый массив и новые объекты, чтобы корректно заметить обновление.
4. **Что делает `preventDefault` при отправке формы?** Отменяет стандартную отправку формы и перезагрузку страницы, позволяя выполнить свою проверку и сохранить данные в состоянии React.
5. **Как отмена оставляет исходную запись без изменений?** В форме редактируется копия значений - черновик. `onSave` вызывается только после проверки и нажатия «Сохранить».
6. **Зачем форме `key` при смене редактируемого id?** `key={event.id}` создаёт новую форму при переходе к другой записи и заново инициализирует её черновик.
7. **Почему фильтр не должен заменять полный массив?** Фильтр - только временное отображение. Если заменить общий список отфильтрованным, скрытые записи будут потеряны.
8. **Что произойдёт после обновления страницы и почему?** Вернутся демонстрационные мероприятия, потому что состояние `useState` живёт только в памяти вкладки, а постоянное хранилище не используется.
